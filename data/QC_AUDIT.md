### 2. 原文独立核验

导入脚本逐条检查：原文句是否出现在所引段落正文中（规范化空白与全半角；以「 / 」分隔的多段引文各段分别命中亦算）。
结果写入每条关系的 `evidence_in_passage`，与上游的 `evidence_verbatim` 并列保留。

| 上游标记 | 本站核验 | 条数 |
|---|---|---:|
| 逐字 | 见于所引段落 | 23,195 |
| 逐字 | **未见于所引段落** | **445** |
| 非逐字 | 见于所引段落（仅空白 / 全半角差异） | 69 |
| 非逐字 | 未见于所引段落 | 341 |
| — | 段落无法解析 | 4,330 |

- 可解析的 24,050 条中，**23,264 条（96.7%）原文确在段内**。
- 上游标为逐字却找不到的 445 条中，312 条来自《何廉臣医案》，多是把医案**标题**当作证据（标题不在正文段落里）；
  另 133 条来自当代病案。
- 全部 786 条未命中里有 206 条来自当代病案（含上述 133 条）：其中 49 条忽略标点与空白后即可命中，
  152 条是对病案的归纳转述而非原句，5 条含去标识化改写过的年份片段。
- 无法解析的 4,330 条全部来自《绍派伤寒》专著：它们沿用上游旧的 `p#####` 段落编号，
  而本仓库的 `corpus_shaopai.json` 是另一套 `b#####` 重切分，两者不能对应。
  上游若补交 `p#####` 语料，即可纳入核验。

### 3. 本体与基数

本体 1.2.0 原样取自上游 `ontology_spec.json`。

| 检查项 | 结果 |
|---|---|
| 定义域 / 值域违例 | **0** / 28,380 |
| 悬空端点 | 0 |
| 自环 | 0 |
| 重复三元组 | 0 |
| 声明为 0..1 却有多条出边的主语 | **55** |

基数例外按属性：籍贯 `physicianOfPlace` 20 · 源自 `derivesFrom` 14 · 载于 `statedIn` 11 ·
属于六经 `belongsToChannel` 3 · 属于世家 `physicianInFamily` 3 · 子证候 `subPatternOf` 2 ·
机构所在 `institutionAtPlace` 2。典型情形有三类：

- **同一地点的不同写法**：何廉臣的籍贯同时连向「浙江绍兴」「绍兴」「越」，趙宗萬连向「會稽」「山陰」。
- **合方本就有多个来源**：柴平汤「源自」小柴胡汤与平胃散——它正是二方合用，0..1 的声明在此不成立。
  另注意 `derivesFrom` 的值域是著作，但不少宾语其实是方名（三拗汤、平胃散），上游把它们建成了 Work 节点。
- **抽取噪声**：个别学术观点「载于」多达 10 个宾语，其中有「六经总诀」「伤寒要义」这类篇章名而非书名。

V5、V6 的做法是把这些属性改为 0..*；自 V7 起**保留上游声明、如实报告例外**。
OWL 导出中这七条属性不声明为 `owl:FunctionalProperty`，以免推理机把同一主语的不同宾语
推断为 `owl:sameAs`。

数据中出现但规格未声明的属性：Doctrine `proposed_by` · Pattern `note` · Formula `base_formula` ·
Herb `dose` `unit` `processing` · CaseRecord `case_no` `note` `year`。

**去标识化**（`tools/deidentify.py`）：行内患者抬头（姓名 + 性别 + 年龄 + 住院号）改写为「患者（性别，年龄）」（44 处）；
残留 7–8 位编号删除；日历日期只保留年份（772 处）；就诊跨度 `note`（131 处）与逐次就诊日期 `visit_dates`（283 处）
改写为天数；90 岁以上合并。

**写盘前的隐私闸门**：全部输出文本中，患者抬头（姓名 + 性别 + 年龄 + 住院号的行内格式）、身份证号、手机号，
以及运行时从原始文本推导出的患者姓名，计数必须为 0；每条当代记录的**全部字符串字段**（不只正文）还要核验
完整日期、月日、编号也为 0；任何一项不为 0，导入即中止、不写任何文件。本版 24 个推导姓名、残留 0。
派生导出（`nodes.csv`、`edges.csv`、`shaopai_instances.ttl` 等）发布前另做逐文件复核：患者抬头、身份证号、
手机号、推导姓名均为 0；文件中 7–8 位连续数字只出现在节点 ID 的哈希里。

聚合表 `modern_case_profiles.csv` 有 52 / 61 行只有 1–2 例，其中 47 行各对应一名患者；V7 因此只发布至少 3 例的 9 行。
V8 随已去标识化的逐案记录一并发布全部 61 行。

### 6. 其他观察

1. 症状与诊法征象两类有 **442 个同名节点**并存，是两层抽取各自命名所致。
2. 繁简归并只作用于节点名称：机构 `kind` 属性仍有 學校 / 学校、醫社 / 医社 等两写。
3. 证候性质 `nature` 有「湿|热」与「湿热」两种写法，主页统计时合并显示，数据未改。
4. 中药节点上的 `dose` / `unit` / `processing` 是原文所见的抽取值，非药典常规剂量。
5. 古籍方剂的逐味配伍未随交付提供：1,376 首方剂中 620 首有边，「药物组成」共 1,453 条——古籍 41 条，
   当代门诊 1,412 条（83 首自拟方与加减方）；`ingredientRole`、`addHerbIf`、`removeHerbIf`、`hasDosage`
   等关系仍无实例。
6. 7,186 个节点没有任何已抽取关系（多为单次出现的症状 / 治法短语），浏览器中铺在最外一圈。
7. 27,733 条关系（97.7%）仅有单次原文支持。
8. 医案标题中只有 255/660 条含规范病名，其余命名的是证候——这是何廉臣的命题习惯，不是词表缺口。
9. 道地药材前缀（广 / 川 / 杭 / 建 / 云 / 西）与陈 / 真 / 原等品质标记刻意不做归并。
